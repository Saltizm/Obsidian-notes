# contingency

- Predefined action or resources that are INCLUDED within the project used to respond to **Identified risks**. ^3f0d6a
- Unlike [[Recovery Plan]] which is a fallback. Contingency aims to avoid the risk.

Usually held by the project sponsors/ organisation.
Not to be confused with [[management reserves]].

### Planning process
Identify risk $\rightarrow$ create remediation strategy
- Risk should be weighed by their **likelihood** and **impact**
- likelihood: How likely its going to happen
- impact: the cost of the risks happens. This can be closure of communication channels, or loss of data in the case of a data breech

#### Key elements in contingency planning policy
| element                  | explaination                                      |
| ------------------------ | ------------------------------------------------- |
| Scope                    | what risk are covered in the plan                 |
| Resources                | what is needed to carry it out                    |

| Schedules                | schedules for **Testing, Exercises, Maintenance** |
| [[Backups]]              | schedule for backup, and backup storage site      |
| Roles and responsibility | who do what.                                      |

### Reason for contingency
- It is not financially feasible to avoid all risk
- Some risk has to be taken if it is not too costly
### Factors for a good contingency
>[!pointers]-
>- **Reliable** execution plan
>- **Regular** update schedules
>- **Compatibility** to other policies
>- recovery **strats, and time** objectives
>- well planned procedures --> **applicable** to the target level
>- covers all **[[Measures to protect Infrastructure and services|infrastructure]]**

Reliable, Regular, Compatibility, Strats and time, Applicable, Infrastructure.
