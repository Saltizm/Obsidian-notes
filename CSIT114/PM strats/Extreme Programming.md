Extreme programming(  XP ) focuses on taking the *best practices* in system development to the extreme.

 XP focuses on high user involvement and implement features *ad hoc*.


**Common practices**
- Test-Driven Development (TDD):
	- Writing test cases before programming
	- Define scope of code

- Pair programming:
	- Having 2 developers working on the same code simultaneously 
	- Reduce typo blindness as developers can peer review
	- process:
	- One developer will program while the 
	- Other write test cases and improve the code

- Continuous integration:
	- *Shared repository* for code 
	- Frequent changes and integration 

- Collective code ownership:
	- Entire team is responsible and credited for the code base
	- Encourage collaboration and knowledge sharing

- Refactoring:
	- Constant improvement of a feature 
	- No change to function of feature

- Small releases:
	- Frequent and incremental releases
	- Frequent feedback from users

- On-site customer:
	- A rat on the team to verify feasibility and requirements 

- Planning Game:
	- Collaborative process for scheduling 
	- All members have equal say in what to implement next iteration

<h4>Use cases</h4>
**High volatility** - When the project is expected to have frequent changes in demands or is unfamiliar 

**Involved stakeholders** - Can support frequent feedbacks and prototypes. Suitable for projects that require close collaboration with the customer/[[Stakeholders]]. 

**Small to medium team size** - XP is more effective in smaller teams where communication is streamlined

**Short Deadlines** - XP can offer fast prototypes to be rolled out and improve in the future.
